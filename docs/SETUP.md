# 搭建指南

## 1. 准备环境

- 推荐 macOS + Node.js 22（已验证 Node.js 22.14.0），附带 npm。
- 自己可用的 Codex 账号，以及允许创建、发布应用的飞书账号／租户。
- 电脑能够访问 OpenAI、飞书开放平台；天气功能还需访问 Open-Meteo。
- 本机默认端口 18343 未被占用。现有实现只支持同一目录一个服务进程。

解压发布包后进入 `Slo-Buddy` 目录，或进入自己 clone 的源码仓库。

```sh
npm ci
npm run setup
```

初始化创建通用 `config/buddy.json`、空凭证文件和运行目录。重复执行会保留已有文件，不会恢复默认或覆盖配置。不要复制发送者的配置、数据库和登录文件。

## 2. 登录 Codex

使用项目锁定的 CLI，明确选择文件凭证存储：

```sh
./node_modules/.bin/codex -c cli_auth_credentials_store='"file"' login
./node_modules/.bin/codex login status
```

按浏览器提示使用自己的账号登录。当前服务从 `~/.codex/auth.json` 复制认证到隔离的 `.private/codex/` 和画图运行环境，每次任务检查主登录版本，首次运行或主登录变化时同步；因此仅在系统钥匙串里有认证、却没有该文件时，服务无法完成这一步。若设置过其他 `CODEX_HOME`，也要核对默认目录是否存在自己的登录文件。

这是使用本机 Codex 登录的集成，不代表模型调用免费、无限额，也不代表需要接收者提供发送者的 token。用量遵循接收者自己的账号规则。

通用模板中的 `model` 是 `gpt-6-astra`，仅作为当前实现示例；若账号不支持，修改 `config/buddy.json` 的 `model` 为该账号可用型号。当前尚无其他模型供应商适配器。

认证过期时先重新登录。主登录更新后，后续请求会同步隔离副本，不需要删除聊天或记忆。主登录未变化时保留隔离 CLI 自己更新的凭证，避免每次覆盖。画图 worker 使用相同同步入口。此修正解决主登录已变化而隔离副本仍陈旧的问题，并不实现多个独立 OAuth 刷新者之间的全局协调；无人值守的长期部署宜使用单独维护的登录或后续统一认证管理。不要把认证目录发给别人。

参考：[Codex CLI 官方命令说明](https://learn.chatgpt.com/docs/cli/reference)。登录命令与本项目安装的 CLI 帮助核对过，后续版本以对应帮助为准。

## 3. 创建飞书应用

进入 [飞书开放平台](https://open.feishu.cn/)，创建可控租户下的自建应用／智能体，开启机器人能力，记录自己的 App ID 和 App Secret。

编辑本地 `.private/apps/main.env`：在 `FEISHU_APP_ID` 和 `FEISHU_APP_SECRET` 等号后分别填写实际值，不要把密钥填进网页名称字段、背景知识或发到聊天中。该文件不会进 Git。

### 权限

先完成基本聊天，再按所需功能逐项开通应用身份权限。权限名称或旧版 scope 在不同入口可能有差异，最终以该 API 页面和租户后台要求为准。

| 用途 | 权限或配置 |
| --- | --- |
| 私聊接收 | `im:message.p2p_msg:readonly` |
| 群里收到 @ | `im:message.group_at_msg:readonly` |
| 以机器人发送 | `im:message:send_as_bot` |
| 下载消息／引用、资源处理 | 消息读取权限（如 `im:message:readonly`）及 `im:resource`，按相关接口要求开通 |
| 获取群历史，查找未直接附带的图片 | 除消息读取外，还需 `im:message.group_msg` 等该接口要求的群消息权限；它扩大可读取范围，非基本聊天必需 |
| 群成员名称、真实 @ 名单辅助 | 查看群成员权限（`im:chat.members:read`）；姓名仍可能因可访问范围不可用 |
| 思考中的消息表情 | 消息表情回复的写入权限；失败时不阻塞最终回答 |
| 其他机器人 @ 当前机器人 | 搜索“获取群组中其他机器人和用户 @ 当前机器人的消息”权限；服务仍另有机器人白名单 |
| 飞书文档 | 按需开通创建、查看、编辑新版文档；素材处理另需对应云文档素材权限，并给应用访问目标资源的权限 |

飞书开放平台授权和 Slo-Buddy 的权限开关是两层：只开其中一层，工具仍可能不可用。群聊文档访问还需要服务中的资源白名单。

参考：[接收消息](https://open.feishu.cn/document/server-docs/im-v1/message/events/receive)、[获取历史消息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)。

### 事件与发布

在“事件与回调”中选择长连接方式：

- 接收消息：`im.message.receive_v1`。
- 交互式卡片回调：`card.action.trigger`，需要卡片按钮／输入时配置。

项目已经注册这两个处理器，无需配置公网 webhook。若后台要求先检测长连接，先按下一节启动服务并连接应用，再回来保存订阅。

完成应用可用范围、版本发布和需要的管理员审核。不要把后台显示“已开权限”当成已发布、已授权和消息能收发的完整证明。

## 4. 启动、连接与配对

```sh
npm start
```

打开 [配置中心](http://127.0.0.1:18343/)，在「飞书接入」点击“连接”。首次模板 `enabled:false`，服务启动不会自动连接未配置凭证的应用；连接成功会保存启用状态，之后重启自动连接。

在配置中心复制首次配对指令，到对应机器人的飞书私聊发送。也可在另一个终端查看：

```sh
npm run pair -- main
```

该命令只读取当前应用状态，不创建配对文件或改写任务状态。每个应用必须独立配对。

之后发送“你好”，确认最终回复。启用图片／文件／文档等能力前，先完成普通聊天的验证。

## 5. macOS 后台守护

先停止自己启动的前台服务（该终端按 Ctrl+C），再运行：

```sh
npm run service -- install
npm run service -- status
```

当前登录用户下注册 `local.slo-buddy` LaunchAgent，写入 `~/Library/LaunchAgents/local.slo-buddy.plist`，登录后启动，退出后由系统拉起。依赖该项目目录和当时 Node 的绝对路径，不要安装后直接移动目录。

停止守护：

```sh
npm run service -- stop
```

重新启动已停止的守护可再次执行 `install`。若要从后台换回前台，先 `stop`，再 `npm start`，不要重复启动。其他操作系统仅提供前台启动方式，进程管理需自行配置。

## 6. 检查与排错

```sh
npm test
npm run smoke
```

`test` 是本地自动化测试，不需要真实飞书凭证。`smoke` 会实际调用 Codex，消耗账号用量，用来确认认证和模型可用；不等同于飞书完整收发成功。

| 现象 | 先检查 |
| --- | --- |
| 无聊天入口 | 机器人能力、发布、可用范围、管理员审核和当前租户 |
| 已连接但不回复 | 消息事件、配对、群是否由所有者启用、是否真正 @ 了机器人 |
| 直接图能看，历史图看不到 | 群历史读取权限、应用资源范围、话题和历史查询上限 |
| 文档拒绝访问 | 开放平台授权、资源分享、私聊／群聊开关和文档／文件夹白名单 |
| 卡片按钮无反应 | `card.action.trigger` 回调订阅与发布状态 |
| Codex 登录失败或无模型 | 自己的认证文件、隔离副本、模型可用性、网络和账号限额 |
| 后台启动失败 | 先检查 `logs/error.log` 和 `logs/service.log`，以及是否有另一服务占用目录或端口 |

需要代理时，可在本机 `.private/network.json` 中配置 Codex 与天气工具读取的代理环境变量，例如 `HTTPS_PROXY`。它不保证覆盖飞书 SDK 的网络请求，飞书连接还需所在系统网络可达。这不是配置中心可视化功能；修改后重启，且不要随包分发自己的代理认证。不要直接向别人发送未审查的原始日志。

## 带背景知识的定向分发包

若包里包含 `examples/background-knowledge.json`，`npm run setup` 会在尚无背景知识文件时载入它。私聊区为空，指定内容进入共享背景；已有知识不覆盖。附带的群成员 ID 不构成配对或机器人白名单，接收者应在自己的应用中核对实际 ID。
